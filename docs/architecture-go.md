# yukibot Go 架构

> 状态：目标实现。行为以当前 Python 实现和 `docs/architecture.md` 为准，技术选型以本次迁移决定为准。
> 语言：Go（单静态二进制，`CGO_ENABLED=0`）
> Telegram：`gotd/td`（MTProto 用户账号，不是 Bot API）
> 数据库：仅 PostgreSQL，查询由 sqlc 生成
> 形态：模块化单体、端口与适配器、功能纵向切片、显式组合根

Python 树继续留在仓库里，作为行为参照。Go 模块在仓库根目录（`go.mod`），不与 `src/yukibot` 混放。

## 1. 已确定的选型

| 决策 | 选择 | 理由 |
|---|---|---|
| 部署 | 一个 Go 进程 | 与现有单实例 userbot 一致，去掉 uv/Python 运行时 |
| Telegram SDK | 只使用 `gotd/td` | 成熟的 MTProto 库；不引入 Bot API，不并行保留 Telethon |
| 会话 | gotd 文件会话 | Telethon `.session` 不能直接读。首次启动交互登录，不在进程里做 mtgo 转换 |
| 数据库 | 只支持 PostgreSQL | SQLite 不再是运行时后端 |
| 查询 | sqlc + `pgx/v5` | 编译期 SQL 校验。动态 `IN` 使用 `sqlc.slice`；领取任务的多语句事务留在仓储里编排 sqlc 查询 |
| 时间 | `TIMESTAMPTZ` | `available_at`、`created_at`、`updated_at`、总结运行时间都是带时区时刻 |
| 布尔 | `BOOLEAN` | 不再用 SQLite 的 `0/1` |
| JSON | `JSONB` | 路由过滤器和任务 payload。领域代码只看见 Go 结构体 |
| 主键 | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | Telegram chat id 用 `BIGINT`。显式插入 route id 后把序列拨到 `MAX(id)`，保证下一次自动分配是 `max+1`（与现有测试的 7 然后 8 一致） |
| 依赖注入 | 手工组合根 `internal/bootstrap` | 不引入 DI 框架，不扫描插件 |
| 迁移 | 自有 checksum runner | 继续按功能 scope 版本化，不用 bun/Atlas 替换这套不变量 |

统一入口与鉴权链路现以 [`message-stream.md`](message-stream.md) 为准。
消息接收不再在入队前执行命令，所有命令根在队列分发端使用同一授权策略。

## 2. 等价约定

「完全等价」指可观察行为与 Python 实现一致，而不是字节级复刻 SQLite DDL。

必须保持不变的部分：

- 内核状态机：生命周期、事件总线（精确类型、失败隔离、并发、退订）、任务监管、控制面（`/help`、授权、回执、串行、错误文案）。
- 命令语法、帮助文本和用户可见错误字符串。
- Forwarder 的路由匹配、环检测、相册滑动窗口、任务去重键、编辑指纹、重试分类和延迟公式。
- 任务领取的队头阻塞：最小 `id` 的 `pending` 任务如果 `available_at` 未到，本次领取为空，即使更大的 id 已到期。这是现有单 worker 语义。PostgreSQL 在该事务里对选中行 `FOR UPDATE`，但**不用** `SKIP LOCKED` 跳过未到期的队头，否则会改变顺序。
- 成功任务删除行，而不是写成 `succeeded`。失败任务保留 `last_error`。
- 总结的分批、合并、提示词版本 2、渲染和 3900 字符切分。
- 管理员规则：outgoing 命令始终放行；当前登录账号不能被删除；管理模块本身不可关闭。

有意不同的部分：

- 不再接受 `sqlite:///`。`YUKIBOT_DATABASE_URL` 必须是 `postgres://` 或 `postgresql://`。
- 时刻用 `time.Time`（UTC）而不是 Unix `float`。调度算术不变：`available_at = now + albumDelay`。
- Go 迁移是各功能的**收敛后 schema**（Python forwarder v8、management v2、summarizer v3 的结果），不是重放 SQLite `ALTER` 历史。已有 SQLite 文件不由运行中的进程在线升级；换库是停机后的一次性导入。
- Telethon v2 session 迁移逻辑删除。gotd 使用自己的会话文件。
- 导入边界用 Go 的 `go/parser` 测试执行，规则与 Python AST 测试相同。

## 3. 依赖方向

```text
                         bootstrap（组合根）
                      /          |           \
                     v           v            v
                features      kernel       adapters
                    |             ^            |
                    +------ contracts <-------+
```

- `internal/kernel` 只有生命周期、事件、监管、关闭和控制面。不知道 Telegram 和 SQL。
- `internal/contracts` 只有不可变消息、事件和数据库错误。不引用功能、适配器、组合根。
- `internal/adapters` 是跨功能基础设施：PostgreSQL 连接与迁移器、JSON 日志、gotd 客户端、限流、peer 缓存。禁止 import `internal/features`。
- 功能领域包禁止 import `gotd`、`pgx`、其他功能、`adapters` 和 `kernel`。
- 功能自己的外层适配器可以依赖基础设施的窄接口：
  - `internal/features/<name>/store` 使用 sqlc 生成代码；
  - `internal/features/<name>/infra` 把 gotd 客户端适配成该功能的端口。
- 只有 `internal/bootstrap` 和 `cmd/yukibot` 知道全部具体类型。

## 5. 内核

语义与 Python `src/yukibot/kernel` 一致。

- `Feature`：`Name`、`Start`、`Stop`。
- `LifecycleManager` 状态：`new → starting → running → stopping → stopped`，失败进入 `failed`。重复名字在构造时失败。`start` 只允许从 `new` 进入；`running` 上再次 `start` 是空操作。失败时按启动逆序回滚。`stop` 逆序，单个 `Exception` 不阻断其余项，最后聚合成 `LifecycleStopError`。
- `InProcessEventBus` 按**精确动态类型**分发，不把子类型投递给父类型处理器。一次 `publish` 快照订阅列表，并发执行，等待全部结束。单个 handler 的普通错误记入 `DispatchReport`，不取消其他 handler。`context.Canceled` 向上抛出。重复订阅同一个函数指针失败。
- `TaskSupervisor` 持有全部后台任务。取消不算失败。关键任务失败置位 `failure` 信号。关闭后拒绝新任务。`stop` 取消并等待超时。
- `Application.Run` 启动生命周期，然后等待关闭信号或关键任务失败。`finally` 始终停止生命周期。关键失败的原因是 `critical_task_failed`，且不覆盖更早的关闭原因。
- `ModuleController` 管理 `forwarder` 和 `summarizer`。缺省持久化状态视为启用并写回。`management` 不在可关闭集合里。
- 控制面只切第一个 `/token`，其余原文交给功能。`/help` 由框架拥有。已注册命令即使参数错误也消费，未知 `/command` 回到数据面。回执键是 `(chat_id, message_id)`，在 handler 之后写入。未授权响应 `Permission denied.`。handler 异常响应 `Command failed. Check the application logs.`，不回显异常文本。

## 6. 持久化

### 6.1 迁移器

`yukibot_schema_migrations(scope, version, description, checksum, applied_at TIMESTAMPTZ)`，主键 `(scope, version)`。

- 启动时按 `(scope, version)` 排序应用。
- checksum 是各 statement 用 NUL 连接后的 SHA-256，算法与 Python 相同。
- 已应用且 checksum 一致则跳过；不一致则 `MigrationDriftError`，不继续后面的迁移。
- 单个迁移的语句和版本行插入在同一个事务里。失败整段回滚。
- 不降级，不删除功能数据。

收敛迁移：

| scope | version | 结果 |
|---|---|---|
| forwarder | 1 | routes、links、jobs、managed topics、poll cursors、chat access |
| management | 1 | admins、modules、按 account 区分的 command receipts |
| summarizer | 1 | rules、runs、单例 model config（含 prompt 与 concurrency） |

### 6.2 任务领取

单 worker。事务内：

1. `SELECT ... WHERE state = 'pending' ORDER BY id LIMIT 1 FOR UPDATE`。
2. 没有行，或该行 `available_at > now`：提交并返回空。不领取更后面的到期任务。
3. 无 `group_key`：把这一行更新为 `processing`，`attempts = attempts + 1`。
4. 有 `group_key`：再锁定同组、仍为 `pending` 且 `available_at <= now` 的行，一并领取。
5. 返回给领域的 `attempts` 是领取后的值。

`recover_incomplete` 把 `processing` 改回 `pending`，不重置 `attempts`。成功是 `DELETE`。重试公式：若错误里有 `RetryAfter`，延迟取其中最大的秒数（不封顶）；否则 `min(base * 2^(attempts-1), max)`，默认 base `1s`、max `60s`、最多 5 次。永久错误（权限、消息不存在、原生转发不支持、相册映射残缺、结果数量不符）不按指数退避重试。

### 6.3 sqlc

`sqlc.yaml` 的 engine 只有 `postgresql`。生成包 `internal/storage/dbsql`。仓储把 `pgtype`/`jsonb` 转成领域类型，不把 `pgx.Row` 或 SQL 泄漏给服务。

## 7. Telegram 适配器

`internal/adapters/telegram` 持有 gotd 客户端、账号身份、peer 缓存和全进程共享的请求限制器。

限制器与现在相同：全局并发 4，每个 chat 再串行，并且每个 chat 每秒最多 20 次调用（滑动窗口）。

功能不接触 `tg.*` 对象。Forwarder 与 Summarizer 各自在 `infra` 里实现本地端口：解析引用、邀请链接加入、论坛话题、原生转发及复制回退、历史拉取、FloodWait 转成 `RetryAfter`。永久 RPC 错误转成 `PermanentDeliveryError`。网络错误转成 `RetryAfter(1s)`。

更新泵在规范化之后先走控制面。已消费的命令不发布 `TelegramMessageReceived`。命令编辑只识别、不执行。删除事件发布 `TelegramMessagesDeleted`。

登录：`connect` → 已授权则 `get_me` 并填充 peer；否则交互式登录。启动失败时断开并清空身份。

## 8. 功能

### 8.1 Forwarder

职责、模型和流程与 `docs/architecture.md` 第 8 节以及 Python 包一致：路由、过滤、原生转发/复制回退、自动话题、相册、回复映射、编辑和删除同步、轮询游标、成员关系重建。handler 只入队，worker 发送。

命令根 `/route`。停用模块时注销命令。

### 8.2 Summarizer

规则、模型配置、提示词预设、map/reduce 和发送与 Python 包一致。模型调用使用 OpenAI Responses 流式接口，`User-Agent: yukibot/0.1.0`，不把 temperature 和 `max_output_tokens` 发给接口；它们只参与分批预算和展示。命令根 `/summary`。

### 8.3 Management

`/admin` 管理委派管理员和模块期望状态。当前账号与委派管理员权限规则不变。命令回执按 `(account_id, chat_id, message_id)` 存储。

## 9. 启动顺序

```text
1. 校验 Settings，初始化 JSON 日志
2. 打开 PostgreSQL，执行迁移
3. 连接并授权 gotd，加载 peer 和账号身份
4. 启动 task supervisor
5. 启动 management（注册 /admin）
6. 按持久化状态启动 forwarder、summarizer
7. 启动 update pump
8. 等待 SIGINT / SIGTERM 或关键任务失败
9. 逆序停止：停收更新、排空 worker、关闭客户端和连接池
```

任一步失败，已启动的功能逆序释放。

## 10. 配置

环境变量前缀 `YUKIBOT_`，可选读取 `.env`。启动后视为只读。

| 变量 | 约束 | 默认 |
|---|---|---|
| `TELEGRAM_API_ID` | `> 0` | 必填 |
| `TELEGRAM_API_HASH` | 非空白 | 必填 |
| `TELEGRAM_SESSION_PATH` | 路径 | `data/yukibot.session` |
| `DATABASE_URL` | `postgres://` 或 `postgresql://` | `postgres://localhost:5432/yukibot?sslmode=disable` |
| `LOG_LEVEL` | 标准级别名 | `INFO` |
| `FORWARDER_ALBUM_DELAY` | `[0, 10]` 秒 | `0.8` |
| `SHUTDOWN_TIMEOUT` | `(0, 300]` 秒 | `15` |
| `REBUILD_JOIN_MIN_INTERVAL` | `[300, 86400]` | `300` |
| `REBUILD_JOIN_MAX_INTERVAL` | `[300, 86400]` 且 `>= min` | `600` |

日志是单行 JSON。字段名（大小写不敏感）包含 `api_hash`、`password`、`secret`、`session`、`token` 时值替换为 `[redacted]`。

## 11. 测试

- 单元测试使用内存仓储和 fake 端口，覆盖内核、路由、任务状态机、命令文案、总结分批和限流。断言对齐 Python 测试锁定的字符串和数量。
- 集成测试用嵌入式 PostgreSQL 启动真实实例，验证迁移 checksum、漂移回滚、仓储 round-trip 和 `claim_due` 队头阻塞。
- gotd 网关的协议映射用 fake API 做契约测试。真实账号测试不进默认 `go test`。
- `internal/architecture` 用 AST 禁止非法 import。

```bash
sqlc generate
go test ./...
go build -o yukibot ./cmd/yukibot
```

## 12. 新增功能

1. 增加 `internal/features/<name>`，只依赖契约和自己的端口。
2. 在 `db/migrations/<name>` 增加带前缀的表。
3. 在组合根显式构造并注册。
4. 补单元测试；有表就补仓储集成测试。

已有功能的领域代码不应为了新功能修改。跨功能协作只通过契约事件。
